# Формировать страницы на сервере с помощью Thymeleaf

## Контекст и постановка задачи

Интерфейс должен работать в браузере без установки ПО (CON-2) и быть
адаптивным (REQ-INT-001). В команде нет отдельного frontend-разработчика.

## Драйверы решения

* один язык разработки
* время на интерфейс шести экранов
* доступность (REQ-INT-003)

## Рассмотренные варианты

* Thymeleaf
* React SPA
* Vue SPA

## Итог решения

Выбранный вариант: «Thymeleaf», потому что экраны LabQueue — в основном
формы и таблицы, а серверный рендеринг не требует отдельной сборки клиента;
для обновления очереди достаточно небольшого скрипта опроса.

### Последствия

* Хорошо, потому что меньше кода и одна точка проверки прав на сервере
* Плохо, потому что сложные интерактивные элементы делать труднее

### Подтверждение

Ревью кода: шаблоны в `src/main/resources/templates`, JavaScript — только
модуль опроса очереди.

## Плюсы и минусы вариантов

### Thymeleaf

* Хорошо, потому что интеграция со Spring Security и CSRF из коробки
* Плохо, потому что перезагрузка страницы при отправке форм

### React SPA

* Хорошо, потому что отзывчивый интерфейс
* Плохо, потому что отдельная сборка, дублирование валидации

### Vue SPA

* Хорошо, потому что проще React
* Плохо, потому что те же недостатки отдельного клиента

## Дополнительная информация

SDD: представление 002; SRS: CON-2.
